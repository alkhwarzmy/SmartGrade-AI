# تشغيل إصدار المؤسسات

> وثيقة الأساس RC1. راجع [تنفيذ RC2 وحدود تحققه](releases/rc2/implementation.md) و[تشغيله وعقد API الجديد](releases/rc2/operations.md) للتغييرات الحالية.

## حدود التشغيل

هذا مرشح تجربة تجارية على مضيف Linux واحد بقرص محلي. لا تشغّل نسخًا موزعة على SQLite مشتركة أو Drive/NFS، ولا تستخدم Colab لاستضافة عملاء. الصلاحيات والمراجعة جزء من المنتج؛ تهيئة النطاق وTLS والنسخ والمراقبة والسياسة الخاصة ببيانات العميل جزء من تشغيله.

## التثبيت المحلي

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-runtime.lock
python -m scripts.manage init --slug my-school --name "اسم المؤسسة" --email admin@example.com
python -m scripts.manage check
python -m streamlit run app.py
```

الإعداد يطلب كلمة مرور مخفية 12–128 حرفًا، دون حساب افتراضي. للتشغيل غير التفاعلي يمكن استخدام `--password-file` لملف مملوك ومقروء للمشغل فقط (600). لا تمرر كلمة المرور كوسيط CLI أو تحفظها في Git. أضف أعضاء الفريق من إدارة المؤسسة؛ تُسلَّم كلماتهم المؤقتة بقناة مناسبة ويغيرونها عند أول دخول.

## الحاويات وHTTPS

1. جهّز خادم Linux وDocker وCompose، وقرص بيانات ونسخ احتياطية مناسبين.
2. انسخ `.env.example` إلى `.env` وأضف `SMARTGRADE_DOMAIN=your-domain.example` بنطاق تملكه وDNS صحيح. تبقى مفاتيح AI فارغة والإرسال معطلًا إلى حين اعتماده.
3. نفّذ:

```bash
docker compose build
docker compose run --rm --no-deps web python -m scripts.manage init --slug my-school --name "اسم المؤسسة" --email admin@example.com
docker compose up -d
docker compose ps
```

Caddy يستقبل 80/443 ويصدر TLS عند اكتمال DNS والشروط الشبكية، ويوجه `/api/*` إلى API والباقي إلى الواجهة. لم يُنشر التطبيق على نطاق عميل أثناء التطوير. لا تفتح 8000 أو8501 للجمهور؛ لا توجد مصادقة إضافية من reverse proxy تعوض تعيين `SMARTGRADE_MODE=demo` خطأ.

الصورة تعمل بـUID/GID 10001، مع جذر ملفات للقراءة وبيانات في volume محلي و`/tmp` مؤقت. لا تُثبت أدوات الاختبار في صورة الإنتاج. خدمة API لها healthcheck خاص، وتوثيقها التفاعلي معطّل افتراضيًا. حدود Compose الافتراضية 2 CPU و2 GB و256 PID لكل خدمة تطبيق هي حدود موارد، وليست قياسات سعة أو SLA.

### CA مؤسسية أثناء البناء

إذا كان وكيل الشبكة يعيد توقيع TLS، يمكن تمرير حزمة CA موثوقة للمشغل دون تضمينها في طبقات الصورة أو تعطيل التحقق:

```bash
docker build --secret id=proxy_ca,src=/path/to/trusted-ca-bundle.pem -t smartgrade:1.0.0-rc1 .
```

هذا هو المسار الذي استُخدم في اختبار بيئة التطوير بعد فشل بناء أول بسبب سلسلة CA. الشهادة سر BuildKit مؤقت وليست مفتاح تطبيق، ويُتحقق من غيابها من الصورة النهائية. الاتصال بخدمة خارجية من حاوية داخل شبكة مؤسسية قد يحتاج تركيب CA موثوق للقراءة وإعداد `SSL_CERT_FILE`؛ لا تعطل TLS.

## العقود والسعة

الأوامر التالية لمشغل الخدمة على الخادم فقط؛ لا تُعرض في API:

```bash
python -m scripts.manage license --slug my-school --plan school --until 2027-12-31
python -m scripts.manage license --slug my-school --plan school --suspend
```

السريان يفسر تاريخ `--until` حتى نهاية اليوم بتوقيت الرياض، ويُخزن كوقت مطلق للمقارنة. شاشة الإدارة تعرضه بتوقيت الرياض. لا معاملات دفع أو فوترة أو تجديد تلقائي؛ يحدد المشغل الأسعار والعقود والفواتير خارج هذا الإصدار. خفض السعة لا يحذف البيانات؛ يمنع الإضافات الزائدة، وتعطيل المؤسسة يمنع الجلسات من الوصول.

## النسخ الاحتياطي

لا تتضمن نسخة المؤسسة المحمولة حسابات المستخدمين أو قاعدة الهوية. لتحصيل نسخة كاملة قابلة لاستعادة الخدمة:

1. أوقف **كل** عمليتي web/API والكتابات الإدارية.
2. انسخ مجلد `SMARTGRADE_DATA_DIR` كاملًا، متضمنًا `identity.sqlite3` وملفات WAL/SHM إن بقيت، ومجلد `organizations`، إلى مخزن مشفر ومصرح به.
3. اختبر الاستعادة في بيئة معزولة قبل الاعتماد على النسخة، ثم أعد تشغيل الخدمتين.

مثال على Docker لنسخ volume بعد إيقاف التطبيق (Caddy لا يكتب البيانات):

```bash
docker compose stop web api
# انسخ volume smartgrade_data بأداة النسخ المعتمدة على خادمك، واحمِ النسخة ومفاتيح تشفيرها.
docker compose start web api
```

للنسخ المنفصل لمؤسسة، تعمل أداة النسخ تحت قفل المؤسسة مع SQLite Backup API، ولا يلزم وضع قاعدة حية على Drive:

```bash
python -m scripts.manage backup-tenant --slug my-school --output /secure-backups/my-school-unique.zip
```

في Docker نفّذ الأداة داخل الحاوية ثم انسخ الملف من `/tmp` إلى مخزن المشغل؛ لا تحفظه على جذر الصورة المقروء فقط. ملف ZIP غير مشفر من التطبيق؛ التشفير والاحتفاظ والنسخ الخارجية مسؤولية المشغل. فشل النسخ لا يستبدل أرشيفًا موجودًا بالاسم نفسه.

### الاستعادة الكاملة

أوقف الخدمتين، واستعد **كامل** مجلد البيانات بنفس الملكية 10001:10001، ثم شغّل `scripts.manage check` واختبر حسابًا وصورة ودرجة وتقريرًا وسلسلة سجل. استعادة نسخة قديمة تعيد الجلسات التي كانت موجودة عند النسخ؛ قبل فتح الخدمة ألغِ جلسات كل مؤسسة مستعادة بالأمر `python -m scripts.manage revoke-sessions --slug my-school`، ثم أعد تسجيل الدخول. لا تستعد على ملفات حية ولا تدمج قواعد مؤسسات مختلفة يدويًا.

### نقل بيانات MVP

أوقف MVP القديم، وأنشئ المؤسسة الجديدة دون فتح مساحة عملها، ثم:

```bash
python -m scripts.manage import-legacy --slug my-school --source /path/to/old/storage
```

يجب أن تكون مساحة المؤسسة فارغة. المصدر يبقى محفوظًا، والأداة ترفض استبدال بيانات حالية. تحقّق من العينات قبل إيقاف استخدام المصدر نهائيًا. أسماء المراجعين والاعتمادات السابقة تُحفظ كتاريخ موروث، ولا تتحول إلى هويات تجارية موثقة بأثر رجعي.

## الاحتفاظ والحذف

الأداة dry-run افتراضيًا؛ تعرض العدد دون رموز الطلاب. اتفق على المدة مع العميل أولًا، ثم راجع العدد قبل التنفيذ:

```bash
python -m scripts.retention --slug my-school --days 365
python -m scripts.retention --slug my-school --days 365 --execute
```

يحذف التنفيذ بيانات الأوراق الأقدم من المدة بحسب تاريخ الرفع وصورها وسجل درجاتها، ويترك حدثًا مركزيًا بمعرف العملية فقط. لا يحذف تعريفات الاختبارات أو الحسابات أو النسخ الاحتياطية. لا يوجد scheduler مُثبَّت تلقائيًا؛ جدول الأداة بنظام التشغيل بعد اختبار السياسة. الحذف منطقي وليس ضمان محو جنائي لوسيط التخزين.

## المراقبة والاستجابة

راقب `/api/health` و`/api/ready`، وصحة الحاويات، والمساحة الحرة وWAL، وفشل OCR والمراجعات، وأخطاء التسجيل. لا تسجل Authorization أو أجسام login أو نصوص الطلاب. تقييد الدخول داخل التطبيق ليس بديلًا لحماية معدل الطلبات/WAF عند فتح خدمة عامة. جلسات التطبيق 8 ساعات مطلقة أو30 دقيقة خمول، وتتجدد حركة last_seen مع الاستخدام فقط. التحقق يجري على الطلب/التفاعل؛ قد تبقى صفحة قديمة مرئية في تبويب خامد حتى التفاعل التالي.

عند حادث: أوقف الوصول، واحتفظ بنسخة تحقيق وفق سياسة العميل، وألغِ الجلسات ودوّر المفاتيح المتأثرة، وتحقق من المراجعات وسلسلة السجل. مدير الجهاز يملك المخطط والملفات؛ سجل البصمات ليس أرشيفًا مستقلًا ضد مشغل يملك النظام.

## الترقية والتراجع

احتفظ بالإصدار السابق ونسخة كاملة متوقفة قبل الترقية. اختبر مرشح الإصدار ونسخة البيانات في staging، ثم غيّر الصورة وشغّل فحوص الصحة. تهيئة قاعدة الهوية إصدارها1 ولا توجد ترحيلات حذف في هذا الإصدار؛ يرفض البرنامج قاعدة هوية أحدث منه. التراجع بعد تغيير مخطط مستقبلًا يحتاج النسخة الكاملة السابقة، لا تشغيل كود قديم على قاعدة أحدث.

## ما يلزم قبل إطلاق فعلي

مرشح الإصدار لا يثبت اختبار اختراق مستقل أو تحمل أحمال العميل أو سلامة استعادة حجم بياناته أو اتفاق النموذج مع المعلمين. أكمل التحقق الأمني/التشغيلي والتقييم الأكاديمي ومراجعة التراخيص واتفاقية معالجة البيانات والتسعير والعقد الخاص بعميلك. لا توجد شهادات امتثال أو SLA مفترضة.
