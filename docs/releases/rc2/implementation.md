## نتائج التحقق

نجحت الاختبارات الـ95 دون فشل، مع تحذير deprecation واحد من Starlette/httpx، واجتاز Ruff الفحص. تطابق52 ملفًا من مصدر الصورة مع ملفات المشروع، ونجحت تجربة أمر التحقق المستخدم في CI داخل جذر قراءة.

توجد النتائج الآلية في مجلد `evidence/`. الاختبارات الأساسية والإضافية تعمل ببيانات وحسابات اصطناعية فقط. فحص دفتر Colab ينفذ المصدر المستخرج محليًا؛ ليس جلسة Google بحساب المستخدم.

- المتصفح: دخول خاطئ وصحيح، اعتماد 20/20، تنزيلات خاصة، خروج، تغيير كلمة المرور، مشاهد، عزل مؤسسة ثانية وجوال.
- Docker: تشغيل UID10001 وجذر قراءة، غياب شهادة شبكة البناء الخاصة، API و PDF وسجل وواجهة، و HTTP فعلي.
- HTTPS محلي: تحقق CA الاختبار واسم المضيف في API، و WSS للواجهة، ودخول Enter، وعامل طفل فعلي لتقرير Excel وتنزيله. استُخدم استثناء شهادة خاصة للمتصفح وحده؛ تحقق شهادة API مستقل ومفعّل. لا شهادة نطاق عام أو قبول نشر عميل.
- الترقية والتراجع: أنشأ الكود الفعلي RC1 بيانات مصححة، ثم قرأها RC2 بعد الترحيل، ثم شغّل RC1 على استعادة snapshot قبل الترقية. بقيت الدرجة 20 والصور والسجل؛ أُلغيت جلسات النسخة المستعادة، وحُفظت إصدارات المخطط الأصلية.
- Python: فُحصت 55 حزمة runtime، دون ثغرات معروفة مبلغ عنها في مصدر الفاحص وقت التنفيذ. SBOM بصيغة CycloneDX1.6 يصف 55 مكونًا، ولا يُعد فحص ثغرات مستقلًا.

### الأحمال وحد الموارد

اختبار القبول يستخدم 1000 ورقة اصطناعية و 20 مستخدمًا/جلسة عبر 4 مؤسسات و 20 سؤالًا للورقة. زُرعت 4 أوراق بالمسار الفعلي و 996 نسخة من البيانات وملفات الصور؛ هذا اختبار قراءة وتقارير واستعادة، وليس قياس سرعة رفع 1000 ورقة أو دقة OMR حقيقية. الطلبات تقرأ 50 سجلًا في الصفحة وتتحقق من نطاق المؤسسة لكل معرف.

نجح 500 طلب دون أخطاء أو خلط مؤسسات؛ p50=209.27 ms وp95=326.3 ms. استغرقت النسخة المشفرة 9.223 ثانية والاستعادة 3.237 ثانية لهذه العينة فقط، مع بقاء 1000 درجة و2000 صورة وإلغاء الجلسات.

القياسات الرقمية النهائية في `evidence/load.json`:500 طلب قراءة، وأربعة تقارير Excel عبر العامل، ثم نسخة مشفرة واستعادة 1000 درجة و 2000 صورة وإلغاء الجلسات.

**معيار الذاكرة ما زال غير معتمد.** طلب الأمر Docker حد 2GiB، لكن cgroup و Docker stats أظهرا حد 8GiB وإحصاءات مشتركة حتى لحاوية اختبار صغيرة. لا تُنسب هذه الذاكرة للتطبيق، ولا يُعرض استهلاكها كنجاح أو تجاوز للتطبيق. نتيجة الاختبار تفصل `functional_and_latency_passed` عن `memory_acceptance_passed`، ويخرج السكربت برمز 2 عند تعذر اعتماد الذاكرة. يجب إعادته على مضيف Docker يعزل الحدود فعلًا قبل اعتماد هدف 2GiB/80%. مواصفات Compose مقيدة لكن إعدادها وحده لا يثبت تطبيقها في هذه البيئة.

### الأمن والتسليم

أُنشئت GitHub Actions للاختبارات وتحقق الدفتر وفحص Python و SBOM وبناء الصورة وفحص نظامها. إصدارات Actions وصور Python و Caddy وأداة Trivy مثبتة بمراجع ثابتة. فحص صورة النظام المحلي **لم يكتمل**: رفض mirror الوصول، ورفض مصدر GHCR إصدار token بعد تزويد شهادة الشبكة الصحيحة. حُفظ السبب في `evidence/os-scan-blocked.txt`، ولا توجد نتيجة «صفر ثغرات نظام» مختلقة. تُعاد هذه الخطوة من مصدر متاح أو بيئة CI/العميل قبل قبول الإطلاق. إعداد workflow لا يثبت وحده نجاح تشغيله المستضاف.

## الأعمال المفتوحة وشروط الإطلاق

1. إعادة اختبار الموارد بعزل فعلي، وإكمال فحص نظام الصورة؛ لا تُغلق W6/W7 بالكامل قبل ذلك.
2. نطاق وخادم staging حقيقيان: شهادة عامة و WebSocket ورفع وتنزيل وسيط موثوق، وتجربة استعادة على حجم العميل. لم تتوفر بيانات الخادم/النطاق؛ الاختبار المحلي مكتمل فقط.
3. تثبيت جدول النسخ وصلاحيات المفتاح على خادم المشغل، وتجربة timer وربط خرج المراقبة بوجهة تنبيه يختارها؛ الملفات مرفقة ولم يُعدل خادم عميل أو جدول أعماله.
4. جلسة قبول معلم/عميل حقيقية واختبارات وصول إضافية. الخيار الحالي تجربة مُدارة خاصة؛ النشر المفتوح يحتاج قرار SSO/MFA وتقييم أمن مناسب، ولم تُنفذ ميزة MFA شكلية.
5. جمع عينات مصرح بها ومرجعين مستقلين وفق الخطة. أُضيف تقييم محلي مع فحص تسرب الكاتب/المصدر و CER/WER خام ومطبع واتفاق المقالات وخط أساس بشري. لا يوجد تدريب HTR أو رقم دقة جديدة دون بيانات.

دليل التشغيل والترقية والاستعادة في `operations.md`، وبروتوكول البيانات في `evaluation.md`. أدوات إعادة التحقق موجودة في `scripts/`؛ لا تنفذ على بيانات إنتاج تلقائيًا.
