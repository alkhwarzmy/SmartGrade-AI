# تشغيل RC2 والتعافي

## محليًا

Linux و Python3.12، أو صورة Docker المرفقة. تثبيت متحقق البصمات:

```bash
python -m pip install --require-hashes -r requirements-runtime.lock
python -m scripts.manage init --slug my-school --name "اسم المؤسسة" --email admin@example.com
python -m streamlit run app.py
# طرفية ثانية للطابور، وبنفس SMARTGRADE_DATA_DIR:
python -m scripts.worker
# API اختياري على loopback:
python -m uvicorn api:app --host 127.0.0.1 --port 8000 --no-access-log --no-proxy-headers
```

Compose يشغل web و api و worker و Caddy. اسم الصورة `smartgrade:1.0.0-rc2`. يلزم نطاق تملكه و DNS صحيح وإعداد `.env`، ثم `docker compose build` و`docker compose up -d`. المنافذ الداخلية غير منشورة. الشبكة الخاصة 172.31.77.0/24 وعنوان Caddy172.31.77.10؛ إذا تعارضا مع شبكة المضيف، غيّرهما مع `SMARTGRADE_TRUSTED_PROXY_CIDRS` في الخدمة. لا تثق بترويسة عميل من خارج الوسيط المحدد.

الدفتر Colab يعمل بوضع demo ويستخدم OCR اليدوي/المحلي مباشرة؛ لا يحتاج عامل المؤسسات. لا حسابات فعلية أو خدمة عامة من الدفتر.

## API الجديد

- `GET /exams` و`GET /exams/{id}/submissions`: `limit=50` افتراضيًا،1–200، و`offset>=0`. يمكن ترشيح الأوراق بـ`status`؛ المشاهد يرى المعتمد فقط.
- الرفع: `Idempotency-Key` اختياري للتوافق. احتفظ به عند إعادة الطلب بعد انقطاع الشبكة. المؤسسة/المستخدم/الاختبار نفسه والمحتوى نفسه يعيد المعرف نفسه، ومحتوى مختلف 409. إعادة المحاولة المقصودة مفتاح جديد. مفتاح ورقة حُذفت يعيد 409. واجهة المعلم تولد المفتاح تلقائيًا وتتيح بدء محاولة جديدة.
- `POST /submissions/{sid}/ocr-jobs` بجسم`{"revision":1}`؛ و`POST /exams/{id}/report-jobs` بجسم`{"format":"xlsx"}`. كلاهما 202 ومعرف مهمة.
- `GET /jobs/{id}`: حالة وتقدم عند مراحل معلومة؛ لا تقدير زمني مصطنع. `POST /jobs/{id}/cancel` أو`retry`، و`GET /jobs/{id}/result` للتقرير الناجح مع المصادقة.
- حد 20 مهمة نشطة للمؤسسة، وعامل واحد لكل تثبيت، وطفل واحد بمهلة 120 ثانية. بعد موت العامل تتحول running إلى failed، وتستلزم إعادة محاولة واضحة. إلغاء المهمة يمنع نشر ناتجها؛ قد تبقى المعالجة حتى انتهاء مهلة الطفل. لا طلبات LLM في الطابور.
- التقرير المتزامن حتى 200 ورقة؛ الأكبر يحتاج report-jobs. التقرير الخلفي حتى 2500 ورقة، و PDF حتى 2000، ثم تقسيم الاختبار. ملفات التقارير خاصة، صلاحيتها ساعة، وتُبطل بعد تعديل/حذف متعلق باختبارها، ويستكمل العامل مسح الملفات المتعثرة.
- الحذف 204 عند اكتمال الملفات؛202 و`status=deleting` عند التعثر. تُمنع القراءة والتعديل للورقة المعلقة. تستكمل المحاولة في العامل.

## النسخ الكامل المشفر

نسخة المؤسسة القديمة المحمولة ليست بديلًا لنسخة التثبيت الكامل. لا تحفظ SQLite الحية على Drive. احفظ المفتاح منفصلًا عن النسخ؛ فقده يمنع فكها. لا تُرفع بيانات أو مفاتيح إلى Git. الحدود الحالية 20GiB/300000 ملف؛ تحتاج تجهيزات النسخ حتى ثلاثة أمثال حجم البيانات مساحة مؤقتة، والاستعادة مساحة للملف المفكوك والبيانات.

```bash
python -m scripts.manage backup-keygen --output /secure/backup.key
# أوقف جميع الكتابات: web و api و worker وأي أداة تشغيل أخرى، ثم:
python -m scripts.manage --data-dir /srv/smartgrade/data backup-full --output /backups/snapshot.sgb --key-file /secure/backup.key --services-stopped
python -m scripts.manage restore-full --archive /backups/snapshot.sgb --destination /srv/smartgrade/restored-new --key-file /secure/backup.key
```

الأسماء أمثلة لمسارات يجهزها المشغل بصلاحيات مناسبة. المفتاح 32 بايتًا وبصلاحية 600 أو 400 وملكية تسمح بقراءته للمشغل. داخل Docker المستخدم 10001؛ اضبط ملكية دليل النسخ والمفتاح له عند التجهيز. الأداة لا تستبدل وجهة موجودة. تتحقق من GCM والبصمات والمسارات والمخطط والعلاقات والصور قبل نشر مجلد الاستعادة، وتلغي جميع الجلسات، وتوقف المهام القديمة لإعادة محاولة يدوية. تُحفظ إصدارات المخطط كما في snapshot لتسمح بالتراجع إلى كوده الأصلي.

يشمل النسخ الهوية وقواعد كل المؤسسات وصورها وتقاريرها، لا ملفات عشوائية خارج الشجرة المدعومة. النسخ القديمة قد تحتوي ورقة حُذفت لاحقًا؛ لها سياسة احتفاظ مستقلة يحددها العميل. لا تحذف النسخ أو المفتاح تلقائيًا من أجل توفير مساحة.

لجدولة نافذة صيانة يومية 03:00 بتوقيت الرياض: راجع `deployment/backup.sh` وملفي systemd. اضبط WorkDirectory وملف Environment واسم Volume والمفتاح قبل تثبيت timer؛ يتوقف الكتّاب الثلاثة ويُعاد تشغيلهم بـ EXIT trap. لم يُثبت timer على خادم عميل في هذه الجلسة. عدم نجاح الأمر يجب أن يصل إلى وجهة تنبيه التشغيل.

## الترقية والتراجع

1. جهز نسخة مشفرة قبل الترقية باستخدام أداة RC2 مع الخدمات متوقفة، دون تشغيل API/واجهة RC2 على البيانات أولًا.
2. احتفظ بالكود/الصورة القديمة و snapshot ومفتاحه. يبدأ RC2 ترحيلًا إضافيًا v2 تحت قفل المخطط؛ لا يعيد كتابة درجات قديمة. افحص الدخول والنتائج والصور والسجل.
3. عند الحاجة للتراجع، أوقف الخدمات، واستعد snapshot السابق إلى مسار/Volume جديد، ثم شغّل الكود القديم عليه. لا تُشغل RC1 على قاعدة هوية v2؛ يرجع snapshot القديم المخطط الأصلي وتُلغى جلساته.
4. عند الاستعادة إلى مجلد فرعي داخل Volume، وجّه `SMARTGRADE_DATA_DIR` في كل خدمة إلى ذلك المجلد عبر Compose override؛ لا تغيّر Volume الأصلي أو تستبدله قبل تحقق الاستعادة. أي تعديلات بعد وقت snapshot تحتاج تسوية يدوية قبل التراجع.

الاختبار `python -m scripts.upgrade_smoke` يشغّل RC1 الحقيقي من Git للتحقق من المسار؛ يحتاج سجل المستودع، ولا يعمل داخل دفتر المصدر المستخرج بلا Git. زمن الاستعادة في اختبار 1000 ورقة خاص بهذه العينة؛ اتفق على RPO/RTO بعد قياس حجم العميل.

## المراقبة والاستعادة الإدارية

`GET /ready` يتحقق من SQLite والقدرة على كتابة ملف اختبار واحتياط قرص 64MiB افتراضيًا. `SMARTGRADE_MIN_FREE_MB` يضبط الاحتياط. يعرض المدير `/admin/operations` مؤشرات مؤسسته فقط؛ عدادات HTTP مؤقتة لكل عملية. كل رد له X-Request-ID، وسجل API يسجل قالب المسار والحالة والزمن دون جسم الطلب أو token.

```bash
python -m scripts.manage monitor
python -m scripts.manage recover-admin --slug my-school --email admin@example.com
```

المراقبة تخرج برمز 1 للتنبيه إلى قرص/عامل/تدقيق متأخر/حذف معلق؛ اربطها بجدولة ووجهة تنبيه يملكهما المشغل. استعادة المدير لحساب إداري موجود فقط، تطلب كلمة مؤقتة مخفية أو ملفًا محميًا، وتلغي جلساته وتلزمه بالتغيير. لا تتجاوز تعليق المؤسسة أو الترخيص. لا مسار استعادة مجهول عبر HTTP.

العامل يعيد التدقيق بالترتيب، ويعيد الحذف، وينظف التقارير المنتهية، ويفحص الصور اليتيمة دوريًا. الصورة المرتبطة بأي صف، ومنها صف الحذف المعلق، لا تُحذف كمخلفات؛ الملفات غير المرتبطة تحتاج عمر ساعة على الأقل.
