# القيود وخطوات التوسع

- OMR v1 فقط؛ لا تكيف تلقائي مع تخطيطات أوراق مختلفة. المربعات الأربع والاتجاه والحلقات شروط إلزامية. الصور المقصوصة أو شديدة المنظور/الظلال تُرفض أو تحتاج مراجعة. لا تُنسب نسبة دقة واقعية إلى اختبار اصطناعي.
- Tesseract خط أساس عربي محلي. لا يوجد نموذج HTR معتمد لخط اليد ولا CER/WER على خط يد حقيقي. الإدخال اليدوي مسار مكتمل.
- مزود LLM اختُبر بعقد HTTP محاكى فقط. يحتاج مفتاحًا ونموذجًا وشبكة وموافقة بيانات وتكلفة. توافق المزود وجودة التصحيح في الخدمة الحية لم يُختبرا.
- لا توجد مصادقة أو صلاحيات أو فصل مؤسسات أو حماية لسجل التدقيق من مدير الجهاز. التشغيل محلي لمعلم موثوق.
- المعالجة متزامنة، ولا يوجد طابور دفعات أو استئناف لمهام خلفية. رفع صور PNG/JPEG فقط، مع سؤال مقالي واحد لكل اختبار مقالي.
- تعريف الاختبار ثابت بعد الإنشاء. تعديلات المفتاح والمعايير تستلزم اختبارًا جديدًا، للحفاظ على معنى النتائج السابقة.
- النتائج تتعامل مع كل تسليم مستقلًا، دون سجل طلاب مركزي أو دمج تلقائي لصفحات امتحان متعدد الأسئلة.
- تصدير نتائج PDF بالعربية، وCER/WER/QWK على بيانات مستقلة، والتقييم المؤسسي، والتدريب والنشر العام مؤجلة.
- لا حذف تلقائي ولا نسخ احتياطي آلي ولا ضمان محو فيزيائي للقرص. الحذف منطقي ويشمل الملفات والسجلات الحالية؛ سياسة النسخ الاحتياطية مسؤولية المشغل.
- قاعدة البيانات في الإصدار الأول تُنشأ تلقائيًا؛ لا توجد ترحيلات مخطط بين إصدارات مستقبلية بعد. أضف Alembic قبل تغيير مخطط قاعدة مستخدمة.

الأولوية التالية: جمع عينات حقيقية مصرح بها، تثبيت بروتوكول تقييم مستقل، اختيار HTR عربي مناسب وترخيصه، اختبار اتفاق التصحيح مع المعلمين، ثم المصادقة والعزل والمهام الخلفية قبل تجربة مؤسسية.
