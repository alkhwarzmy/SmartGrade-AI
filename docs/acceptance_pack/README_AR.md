# حزمة اختبارات SmartGrade العربية — الإصدار الأول

هذه الحزمة بيانات اختبار اصطناعية جاهزة، وليست نتيجة قياس لدقة النموذج. تتضمن 4 اختبارات و20 سؤالًا و32 ورقة مقالية، و12 صورة OMR، و4 ملفات مرفوضة عمدًا، و18 سيناريو استخدام. الدرجات المرجعية مؤلفة وفق المعايير، ولم يحكّمها معلمون مستقلون.

## بداية سريعة

1. افتح teacher_guide.html من الحزمة؛ يحتوي الأسئلة والإجابات النموذجية والمعايير ودرجات الحالات.
2. أنشئ اختبار مادة واحدة في الواجهة بنسخ الأسئلة والمعايير كما هي. ملفات exams/*.json متاحة لاستخدام عقد API عند الحاجة.
3. ارفع ورقة A من essays/<subject>، برمز يطابق اسمها. استخرج النص وراجعه، ووزّع الإجابات على الأسئلة واحفظها.
4. سجّل اقتراح النموذج قبل أي تعديل أو اعتماد من المعلم، وقارنه بملفات references. ابدأ أيضًا بورقة D الخاطئة، ثم C الجزئية، ثم B المعاد صياغتها.
5. دوّن النتيجة في results_template.csv. الخانات الفارغة مقصودة؛ لم يُشغَّل نموذج نيابة عنك.

اختبار جميع الأوراق بالنموذج قد ينفذ طلبات مدفوعة. توليد الحزمة وفحص صورها لا يحتاجان مفتاح AI ولا ينفذان طلب مزود. لا ترسل أي مفتاح في المحادثة.

## اختبر المراحل بصورة منفصلة

- **التصحيح وحده:** أدخل إجابات ملف *.txt يدويًا في حقول الأسئلة واحفظها. لا تنسخ عنوان السؤال أو الدرجة إلى حقل الإجابة. سجّل اسم النموذج وإصدار التطبيق والاقتراح قبل تعديل المعلم.
- **OCR وحده:** استخرج الصورة وقارن النص بما هو مطبوع فعلًا في ocr_references. هذه الملفات تشمل عناوين الورقة وأرقام الأسئلة المطبوعة. السؤال الذي ليس له جواب يبقى فارغًا بعد التدقيق.
- **المسار الكامل:** ارفع الصورة، استخرج النص، دققه ووزّعه، ثم اطلب الاقتراح. سجّل إن عدلت OCR؛ فذلك يؤثر في تفسير النتيجة.
- **خط اليد:** اطبع print/handwriting_sheets.pdf واكتب إجابات إحدى الحالات بيدك ثم صوّرها. سجّل الإضاءة والجهاز والكاتب برمز. الصور الأصلية في الحزمة مطبوعة؛ لا تُستخدم نتيجتها لإعلان دقة خط اليد.

## ملفات رفض الرفع

- invalid/fake.png: امتداد صورة ومحتوى نصي.
- invalid/too-small.png: 64 × 64 بكسل.
- invalid/too-many-pixels.png: 4100 × 4000، أكثر من 16 مليون بكسل، رغم صغر حجم الملف المضغوط.

المتوقع رفض كل ملف دون إنشاء ورقة جديدة. انخفاض حجم الملف بالميجابايت لا يعني قبول أبعاده.

## سيناريوهات التشغيل

تفاصيل السيناريوهات الثمانية عشر في functional_scenarios.json، وملخصها في جدول تسجيل النتائج. تشمل إضافة وحذف الأسئلة، رمز الطالب، تكرار الرفع، عدم حفظ النص، تعارض جلستين، الأدوار والعزل، التصدير، Android والكاميرا، وإعادة التشغيل. استخدم مؤسسة وحسابات اختبار اصطناعية منفصلة عن بياناتك الفعلية. لا تنفذ الحذف أو تغيير إعداد مزود على بيانات إنتاجية لاختبار الواجهة.

## تفسير النتائج

- هذه الحزمة تكشف أخطاء وتساعد على مقارنة إصدارات، ولا تعطي اعتمادًا إحصائيًا لجودة النظام.
- درجة المعلم المعدلة ودرجة النموذج قبل التعديل تسجّلان في عمودين مستقلين.
- فرق A وB يستحق المراجعة لأن المعنى متكافئ وفق المعايير. راجع أيضًا أي درجات موجبة في D أو E، وأي درجة غير صفرية لسؤال فارغ.
- راجع اختلاف C على مستوى كل عنصر؛ الدرجة المرجعية مؤلفة وقد تحتاج تحكيمًا تربويًا قبل تحويلها إلى معيار إطلاق.
- ملف validation.json يختبر بنية المراجع ومجاميعها وصور OMR والملفات المرفوضة. لا يعني أنه اختبر اقتراحات LLM أو خط اليد.
- جميع حالات الاستخدام في results_template.csv تبدأ «لم يُنفذ». اكتب النتيجة الحقيقية بدل تحويل نجاح توليد الملفات إلى نجاح تشغيل النظام.

```bash
python -m scripts.build_acceptance_pack --output /tmp/smartgrade-test-pack-new
```
