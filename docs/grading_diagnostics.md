# تشخيص التصحيح وإصلاح أخطاء اعتماد الدرجات

من صفحة المراجعة اضغط «فحص سبب تعثر التصحيح». يوضح التقرير:
- هل النص الظاهر محفوظ؟ وهل تم حفظ توزيع إجابات الأسئلة؟ الفراغ بعد حفظ التوزيع يختلف عن عدم التوزيع.
- سبب عدم جاهزية المزود: إعداد المشغل أو المفتاح أو النموذج أو سياسة المؤسسة.
- حالة محرك OCR، وعدد أحرف إجابة كل سؤال، ومصدر الدرجة الظاهرة: اعتماد المعلم أو اقتراح النموذج.
- آخر فشل معالجة مسجل برمز ثابت، مع توضيح إن تغيرت المدخلات بعده.
يمكن تنزيل التقرير دون إجابات الطلاب أو الأسئلة أو مفاتيح المزود. الفحص نفسه لا يستدعي خدمة مدفوعة.
في Android يوجد الزر نفسه، ويظل اعتماد المعلم معروضًا عند وجود اقتراح سابق.

## عيوب أُعيد إنتاجها وإصلاحها
1. كانت واجهة الويب تسمح بطلب اقتراح أو اعتماد درجة مع وجود نص ظاهر غير محفوظ؛ الطلب يستخدم النص القديم.
   أصبح طلب التصحيح والاعتماد ينتظران حفظ النص، مع رسالة واضحة.
2. كان فشل OCR أو المزود يلغي اعتمادًا سابقًا رغم عدم تغيير النص أو الإجابات.
   أصبح الفشل يسجل في التاريخ مع بقاء الدرجة والاقتراح والتقارير المعتمدة. تغيير الإجابة الفعلي ما زال يلغي الاعتماد.
3. كان Android يفضل الاقتراح القديم على الدرجة التي عدلها المعلم واعتمدها عند إعادة فتح الورقة.
   أصبح عرض المعلم المعتمد هو المرجع الأول.
4. كان عدم توزيع الإجابات يختلط بإجابات فارغة. يلزم حفظ التوزيع للاختبار متعدد الأسئلة قبل اقتراح أو اعتماد الدرجات.
5. كانت أخطاء المزود تجمع في رسالة واحدة، وأخطاء OCR في العامل تفقد سببها.
   أصبحت رموز الإعداد والاعتماد والحصة والمهلة والسياق والمخرجات والأدلة منفصلة.
   فشل طلب فعلي يعيد رقم المراجعة الجديد ليحتفظ Android بمسودته دون إعادة طلب برقم قديم.

## إعدادات توافق النموذج
- LLM_TOKEN_PARAMETER=auto افتراضيًا: max_completion_tokens لعائلات gpt-5 وo1/o3/o4؛ وmax_tokens للنماذج الأخرى.
  يمكن تحديد أحد الاسمين صراحة لمزود متوافق بعقد مختلف.
- LLM_MAX_OUTPUT_TOKENS: اختياري، بين128 و32000. ارتفاع الحد قد يزيد تكلفة الطلب.
- LLM_TEMPERATURE: اختياري؛ الافتراضي0 للنماذج التقليدية، ولا يرسل افتراضيًا للنماذج الاستدلالية.
لا توجد إعادة محاولة تلقائية لطلب مدفوع. الرد المبتور أو غير المطابق أو الدرجة الموجبة دون اقتباس لا يُحفظ اقتراحًا.
التحقق من الاقتباس وحده لا يثبت صحة الدرجة علميًا.

## تشخيص دون تكلفة نموذج
من جذر المشروع:
```sh
python -m scripts.diagnose_grading --ocr-sample --output outputs/grading-diagnostic.json
```

يتحقق من6 حالات اصطناعية، ويقيس OCR على صورة مطبوعة معروفة، ويعرض model_evaluated=false ما لم تُقدم مخرجات.
القيم الفارغة في مقاييس التصحيح تعني أن النموذج لم يُختبر؛ ليست خطأ صفريًا أو دقة100%.

لمقارنة مخرجات سبق حفظها أنشئ JSON بالشكل {"student-c": {"questions": [...]}} ثم:
```sh
python -m scripts.diagnose_grading --predictions predictions.json --output outputs/grade-comparison.json
```

يعرض الفارق لكل معيار وسؤال والمجموع، ويفصل الرد غير الصالح عن الدرجة المختلفة.
التشغيل الفعلي الاختياري يحتاج --live و--consent-to-external-processing-and-cost بالإضافة إلى إعدادات المزود وسياسة التشغيل.
أداة القياس الاختيارية مخصصة لعينات اصطناعية لدى المشغل ولا تغير بيانات مؤسسة أو تعتمد درجات، وتستثني الإجابات الفارغة.
ست عينات ودرجات مرجعية معدة داخليًا لا تكفي لإثبات دقة عامة أو جودة الخط اليدوي.
